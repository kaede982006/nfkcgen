# NFKC 연구용 문자열 생성기 (GTK 4 / C)

GTK 4 기반으로 1류·2류·3류 실험용 문자열을 생성하는 Linux 데스크톱 프로그램입니다.

## 빌드 및 실행

Debian 13 기준 의존성:

```sh
sudo apt update
sudo apt install build-essential pkg-config libgtk-4-dev
```

한국어 등 다국어 입력(fcitx5)을 쓰려면 GTK4용 입력기 모듈도 설치하고 fcitx5를 다시 시작합니다.

```sh
sudo apt install fcitx5-frontend-gtk4
```

프로그램은 시작 시 `GTK_IM_MODULE`이 비어 있으면 `fcitx`로 설정합니다. 데스크톱에서 이미 다른 입력기(ibus 등)를 지정했다면 그 값을 그대로 존중합니다.

빌드 및 실행:

```sh
make
./nfkc-string-generator
```

## 문자열 유형

- **1류 — 정규 문자열:** 요청에 제시된 1류 예시의 외부 유니코드 문자 집합에서만 생성합니다. 일반 문자열 입력란은 비활성화됩니다.
- **2류:** 입력란의 비어 있지 않은 줄이 정확히 하나여야 합니다. 해당 문자열을 결과 맨 앞에 놓고 뒤에 외부 유니코드 문자를 붙입니다.
- **3류:** 입력란의 비어 있지 않은 줄이 두 개 이상이어야 합니다. 입력 순서를 유지하며 각 일반 문자열 앞·사이·뒤에 외부 유니코드 문자 구간을 둡니다.

빈 줄은 무시합니다. 목표 길이는 20~120 코드 포인트이며 기본값은 80입니다. 2류와 3류에서 일반 문자열의 코드 포인트 총합이 목표 길이 이상이면 생성을 거부합니다. 3류는 각 문장 사이와 양 끝에 외부 문자를 최소 한 개씩 둘 수 있어야 합니다.

## 길이 측정과 논문과의 관계

길이는 UTF-8 바이트 수나 화면에 보이는 글자 수가 아니라 **유니코드 코드 포인트 수**로 셉니다. 생성 결과는 원문 기준 목표 길이를 정확히 만족합니다. 결과 아래에 NFKC 정규화 이후 길이와 길이 변화도 표시합니다. 호환 문자가 NFKC 과정에서 여러 코드 포인트로 확장될 수 있으므로 NFKC 후 길이는 120을 넘을 수 있습니다. 이는 확장 현상을 관찰하기 위한 값이며, 이 프로그램이 NFKC 후 길이 제한을 적용한다는 뜻은 아닙니다.

첨부 논문 초안(2026-10-29)은 유니코드 15.1.0 할당 문자 149,878개를 조사해 1,237개 문자가 NFKC 후 두 코드 포인트 이상으로 확장되고, 최대 확장 길이가 U+FDFA의 18 코드 포인트라고 보고합니다. 또한 점자 패턴 U+2800은 NFKC 후에도 바뀌지 않는 예로 제시합니다. 이 프로그램의 세 유형은 논문에서 정의한 분류가 아니라, 요청에 따라 별도로 정한 실험 조건입니다. 외부 문자 집합도 전체 유니코드 할당 문자를 무작위로 뽑는 방식이 아니라 요청 예시를 바탕으로 한 고정 집합입니다.

**예시 적합성 주의:** 1류 예시는 “외부 유니코드 문자만 포함한다”는 사용자 정의에는 맞지만, “NFKC로 바뀌지 않는 정규 문자열”이라는 뜻으로 해석하면 맞지 않습니다. 예시 안의 `ﷺ`(U+FDFA)는 18 코드 포인트로, `⑳`는 `20`으로, `¼`는 `1⁄4`로 확장됩니다. 따라서 이 프로그램은 NFKC 변환 문자를 일부러 외부 문자 집합에서 제외하지 않습니다. 논문의 관찰 대상과 같은 확장 현상을 포함하기 위해서입니다.

NFKC는 시스템 GLib에 포함된 Unicode 데이터 테이블로 계산합니다. 이 테이블의 Unicode 버전은 논문에서 사용한 15.1.0과 다를 수 있으며, 프로그램은 그 테이블 버전을 별도로 고정하지 않습니다. 논문 수치와 엄밀하게 대조할 때는 동일한 Unicode 버전으로 정규화해야 합니다.
